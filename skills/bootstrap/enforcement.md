# Enforcement stage

Makes the gates binding. Five strengths, weakest last: the **host refuses** (required checks on a protected default branch, administrators included); a **local hook refuses** (earlier and cheaper); an **independent record** (the runner from a command's exit or a CI run, a separate session, the review pipeline, the owner); the **author's own word**, which is never a gate step. Three rules hold throughout: no session records a check of its own work; a change is judged by the base branch's copy of the checks and step lists; the files that define the rules change only in a PR the owner reads.

Resumable like the rest: each step's **Detect** says when it is done, so a rerun starts at the first open one. Each step tells the person, in one line, what it stops and what it costs, before asking. Never overwrite an existing file; chain or point to it.

| # | Step | Stops | Costs | Detect | Do |
| --- | --- | --- | --- | --- | --- |
| E1 | **Review route** | The author recording the review of their own change | One session per PR, after the checks | `gate_pr` has `reviewer: session <docs.review_checklist>` with no `if`; no `here` step | Keep `ci`, `live-check` and `reviewer` as in `templates/project.yaml`: the checklist, by kind of diff, on every PR, after the steps that cost no model tokens, so a prose-only diff with a false statement fails. Replace each `here` step of `gate_pr` with a `command` or `session` step |
| E2 | **Stack decisions and exceptions** | Plans and reviews with nothing to check a tool choice against | Writing down choices the project already made | `docs.stack_decisions`, `docs.stack_tools`, `docs.stack_exceptions` point to existing files | Point to existing ones, or fill `templates/review/stack-decisions.md`, `stack-tools.md`, `stack-exceptions.md` with the owner. Copy `templates/review/tool-fit.md` and `stack-hunt.md` beside the other question files; add `paths.mechanism`, the `tool-fit` step of `gate_pr` and the `stack` step of `gate_phase` |
| E3 | **Git hooks** | A commit of planned files without the plan, from any agent or person | One file and one `git config` per clone | `lc-gate enforcement` shows the git pre-commit hook on | Copy `templates/githooks/pre-commit` to `.githooks/pre-commit` (an existing hook: call `lc-gate plan-check --staged` from it), commit it, run `git config core.hooksPath .githooks`. `core.hooksPath` replaces `.git/hooks`: move a hook kept there first |
| E4 | **CI templates** | A PR merging without its body record or with a phase marked done without its record; a PR loosening the check that judges it | Two workflows, three small scripts | `.github/workflows/` has the `pr-body` and phase-record jobs, and both run `.agents/ci/from-base.sh` | Copy `templates/ci/from-base.sh` and `pr-body-check.mjs` to `.agents/ci/`, `pr-body.yml` to `.github/workflows/`, and the phase-record step of `pr.yml` into the PR workflow; fill the kit's repository and a pinned commit; set `pr_body` in the project file |
| E5 | **Required checks and protection** | Merging while a check is red or missing, pushing to the default branch, the owner's login (and sessions using it) skipping both | A protected branch: every change goes through a PR | `lc-gate enforcement` shows the host rows on | Name the jobs in `ci.required_checks`; run `lc-gate protect`, show the plan, then `lc-gate protect --yes` once the owner agrees. Where the host's plan refuses, or there is no host or no pull requests, say so, record it in `ci.enforcement`, and go on: the hooks and records still hold. Without pull requests, the plugin hook checks a `git merge` of a branch into the default branch against that branch's PR gate, as it does `gh pr merge` |
| E6 | **Protected rule files** | A PR quietly changing what judges it | The owner reads those PRs | `lc-gate enforcement` shows every `owner reads` row on | List the project file, `.agents/ci/`, the hooks, the workflows, the question files and the stack files in `protected_files` and `owner_approval` (globs, or a pointer to a list kept elsewhere) |
| E7 | **Modes** | Nothing yet: `observe` logs and tells; refusals start by themselves | A few PRs of observing | `gate_pr_mode` and `gate_pr_plan` set | Start at `observe 3`: after three PRs merged with every record the gate enforces without an edit, and the hook says so once. A project that wants refusals from the first PR writes `enforce`. With no host, nothing refuses until a mode enforces, and `--strict` says so |
| E8 | **Check** | Believing a layer is on when it isn't | One command | `lc-gate enforcement --strict` exits 0 | Run it and show the table (`--md` for the board or a PR). A row still off goes back to its step, or to the owner with what it needs |

**What still escapes**, said to the owner at the end: sessions that share the owner's host login can do what the owner can; records are files, not signed; a record proves the review ran, not that it was good; and without a host, a merge made outside Claude Code (a person's shell, another agent) is not checked: git runs no hook before every merge (a fast-forward skips `pre-merge-commit`).
