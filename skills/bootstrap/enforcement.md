# Enforcement stage

Makes the gates binding. Five strengths, weakest last: the **host refuses** (required checks on a protected default branch, administrators included); a **local hook refuses** (earlier and cheaper); an **independent record** (the runner from a command's exit or a CI run, a separate session, the host's checks, the owner); the **author's own word**, which is never a gate step. Three rules hold throughout: no session records a check of its own work; a change is judged by the base branch's copy of the checks and step lists; the files that define the rules change only in a PR the owner reads.

Resumable like the rest: each step's **Detect** says when it is done, so a rerun starts at the first open one. Each step tells the person, in one line, what it stops and what it costs, before asking. Never overwrite an existing file; chain or point to it.

| E4 | **CI templates** | A pull request merging without its checks or its body record; a pull request loosening the check that judges it | Two workflows, two small scripts | `.github/workflows/` has the `verify-pr` and `pr-body` jobs, and `pr-body` runs `.agents/ci/from-base.sh` | Copy `templates/ci/from-base.sh` and `pr-body-check.mjs` to `.agents/ci/`, `pr.yml` and `pr-body.yml` to `.github/workflows/` (and `formal.yml` where the project has a model); fill the kit's repository and a pinned commit; set `pr_body` in the project file |
| E5 | **Required checks and protection** | Merging while a check is red or missing, pushing to the default branch or a stage branch, the owner's login (and sessions using it) skipping either | Protected branches: every change goes through a pull request | `lc-gate enforcement` shows the host rows on | Name the jobs in `ci.required_checks`; run `lc-gate protect`, show the plan, then `lc-gate protect --yes` once the owner agrees. The lead runs `lc-gate protect --branch <stage branch> --yes` for each stage branch it cuts. Where the host's plan refuses, or there is no host or no pull requests, say so, record it in `ci.enforcement`, and go on: the hook and the records still hold the stage exit |
| E6 | **Protected rule files** | A PR quietly changing what judges it | The owner reads those PRs | `lc-gate enforcement` shows every `owner reads` row on | List the project file, `.agents/ci/`, the hooks, the workflows, the question files and the stack files in `protected_files` and `owner_approval` (globs, or a pointer to a list kept elsewhere) |
| E7 | **Modes** | A stage entering the default branch without its records | Nothing: the hook reads files | `gate_pr_mode` and `gate_pr_only` set | `gate_pr_mode: enforce` and `gate_pr_only: default-branch`, as the template has them. `observe` or `observe <n>` only where the owner wants to watch first. With no host, nothing refuses until the mode enforces, and `--strict` says so |
| E8 | **Check** | Believing a layer is on when it isn't | One command | `lc-gate enforcement --strict` exits 0 | Run it and show the table (`--md` for the board or a PR). A row still off goes back to its step, or to the owner with what it needs |

**What still escapes**, said to the owner at the end: a pull request into a stage branch needs the swarm's verdict by the playbook's rule only, which no hook reads, so the host's checks are all that refuses there; sessions that share the owner's host login can do what the owner can; records are files, not signed; a record proves the review ran, not that it was good; and without a host, a merge made outside Claude Code (a person's shell, another agent) is not checked: git runs no hook before every merge (a fast-forward skips `pre-merge-commit`).
