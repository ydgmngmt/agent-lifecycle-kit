# Machine-specific pieces

Nothing machine-specific belongs in this repository. What differs per machine is set in the shell profile, or in the `sessions:` block of a project file where it says so.

- **A terminal tab per new session.** The owner sees every session in his terminal, and a spawn never takes the focus from the window he is in. `lc-spawn` itself starts sessions in the background and opens nothing; set `LC_OPEN_TAB` (or `sessions.open_tab`) to a command that receives the window name as `$1`, opens a terminal tab running `lc-view "$1"`, and gives the focus back if the terminal took it. Check once, with the owner's own window in front, that the focus stays. For a session that already runs, call the same command with its name.
- **Session overrides.** `LC_TMUX_SESSION` overrides `sessions.tmux_session` for `lc-spawn`, `lc-close` and `lc-view`; `LC_AGENT_CMD`, `LC_MODEL`, `LC_EFFORT` and `LC_AGENT_FLAGS` override the rest of the block for `lc-spawn`. A gate session (`lc-gate run`) runs on `sessions.gate_model` and `sessions.gate_effort` (the template: `opus`, `high`), never the lead's `LC_MODEL`/`LC_EFFORT`. For `claude`, `lc-spawn` watches the new window for up to `LC_TRUST_WAIT` seconds (15) and answers the folder-trust prompt for a folder inside the repository's worktrees or `handoff_dir`; for any other folder it prints that the session waits on it.
- **Lean gate sessions.** `sessions.gate_flags`, when set, replaces `sessions.agent_flags` for the sessions `lc-gate run` starts; `{kit}` in it is this kit's directory. With Claude Code (checked against `claude --help`, 2.1): `--strict-mcp-config --setting-sources '' --settings '{"skipDangerousModePermissionPrompt":true}' --plugin-dir {kit} --permission-mode bypassPermissions` starts with no MCP server, no user, project or local settings (so no other installed plugin), and this kit as its only plugin: the `review` skill loads and `lc-gate record` runs. Keep the permission flag your `agent_flags` has. The Thermos rubrics are files in this kit (`vendor/thermos/`), so the stage exit's sessions need no other plugin. A question file that names a skill of another plugin needs that plugin's `--plugin-dir` too. Measured on one review: 34,421 tokens before the first word with the user's setup, 22,805 this way.
- **pstack's models.** pstack reads one line per role from `~/.claude/rules/pstack-models.md`, which Claude Code loads into every session; pstack's `setup-pstack` skill writes it. The kit expects every build role on `opus medium`, `interrogate reviewers` on `opus high`, and `swarm workers: sonnet medium` (the swarm's run lane and trivial edits). Review runs one step above the build: the swarm's audit lane and the stage exit's sessions are Opus at high effort; the arena and interrogate lines are used only by a critical brief. `LC_PSTACK_DIR` overrides where `lc-pstack` finds the plugin.
- **Tools.** [Baseline tools](tools.md) lists what a machine and CI need (mise for TLC, elan for Lean, Bombadil, Playwright); `lc-tools` shows what is missing here.
- **Memory.** `sessions.memory_floor_mb`: `lc-spawn` starts no session while `/proc/meminfo` shows less available.
- **Git 2.36 or later.** A follow-up review's scope is `git log -p --first-parent --remerge-diff`, and a merge of main holds a record only when `git show --remerge-diff` prints nothing; with an older git no record holds across a merge.
- **The board.** `LC_BOARD_PORT` and `LC_BOARD_DIR` override `board.port` and `board.data_dir` for `lc-board`.
